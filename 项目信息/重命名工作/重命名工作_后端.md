# 重命名接口设计方案（按执行顺序）

## 1. 接收请求与参数解析
- **URL**: `PATCH /file`
- **请求体格式**: JSON
- **参数**:
  - `id` (Long, 必填): 待重命名的文件/文件夹的ID
  - `newName` (String, 必填): 新名称
- **解析**: Spring MVC 自动将JSON绑定到控制器方法的参数对象。

## 2. 基础参数校验
- **非空校验**: `id` 和 `newName` 均不能为 `null` 或空字符串。
- **格式校验**: 使用注解或手动校验，确保 `newName` 长度在1~255字符之间。
- **非法字符校验**: `newName` 不能包含路径分隔符 `/` 或 `\`（根据系统统一使用 `/` 的约定，禁止包含 `/`），可选限制其他特殊字符（如 `< > : " | ? *`）。
- 若校验失败，直接抛出参数异常，由全局异常处理器返回400响应。

## 3. 权限校验
- 从当前会话（如 `HttpSession`）中获取登录用户ID（`userId`）。
- 根据 `id` 和 `userId` 查询 `folder` 表：
  ```sql
  SELECT id, path, name, type, user_id FROM folder WHERE id = #{id} AND user_id = #{userId}
  ```
- 若查询结果为空，表示记录不存在或不属于当前用户，抛出权限异常（403或自定义错误码）。

## 4. 获取原记录信息
- 从查询结果中获取：
  - `oldPath`: 原完整路径（如 `/docs/a.txt`）
  - `oldName`: 原名称（如 `a.txt`）
  - `type`: 类型（`file` 或 `folder`）
- 计算父路径：
  - 若 `oldPath` 包含 `/`，则父路径 = `oldPath.substring(0, oldPath.lastIndexOf('/'))`（例如 `/docs/a.txt` → `/docs`）；若 `oldPath` 就是 `/`（根目录），则特殊处理（通常不允许重命名根目录，可在此步拦截）。
- 构造新路径：
  - `newPath = parentPath + "/" + newName`（注意处理父路径为空的情况，如根目录下文件：`"/" + newName` 应合并为 `"/" + newName`，避免双斜杠）。

## 5. 重名冲突检查
- 在 `folder` 表中检查同一用户下是否存在与新路径冲突的记录：
  ```sql
  SELECT COUNT(*) FROM folder WHERE path = #{newPath} AND user_id = #{userId}
  ```
- 注意：如果新路径与原路径相同（即新名称与原名称相同），理论上不算冲突，但业务上可视为无变化，直接返回成功或提示无变化。本方案按常规处理，若新名称与原名称不同，则必须检查冲突；若相同，则跳过后续更新，直接返回成功。
- 若存在冲突（`count > 0`），返回409 Conflict错误。

## 6. 执行重命名操作（事务内）
### 6.1 更新当前记录
- 更新当前记录的 `name` 和 `path` 字段：
  ```sql
  UPDATE folder SET name = #{newName}, path = #{newPath} WHERE id = #{id} AND user_id = #{userId}
  ```
- 注意：更新前需再次确认记录未被他人修改（可选乐观锁），但简单场景下可不做。

### 6.2 若当前记录是文件夹（`type = 'folder'`），递归更新所有子项的路径
- 构造旧路径前缀：原路径 `oldPath` 后加 `/` 作为匹配前缀（例如原路径 `/docs`，则前缀为 `/docs/`）。
- 执行批量更新语句（MySQL）：
  ```sql
  UPDATE folder 
  SET path = REPLACE(path, #{oldPath}, #{newPath}) 
  WHERE user_id = #{userId} 
    AND (path = #{oldPath} OR path LIKE CONCAT(#{oldPath}, '/%'))
  ```
  - 注意：条件中 `path = #{oldPath}` 会匹配当前文件夹自身，但当前记录已在6.1中更新，此处应排除自身或允许重复更新（但REPLACE对自身无影响）。为安全，可限定 `id != #{id}` 或者使用 `path LIKE CONCAT(#{oldPath}, '/%')` 仅匹配子项。
  - 使用 `REPLACE` 函数将路径中的旧前缀替换为新前缀。
  - 仅更新属于该用户的记录，避免跨用户误改。
- 如果数据库不支持 `REPLACE`，可先查询所有子项ID，再逐个更新，但性能较差。推荐使用批量更新。

### 6.3 事务控制
- 整个更新操作（6.1和6.2）必须在同一个数据库事务中执行，使用 `@Transactional` 注解保证原子性。
- 若任一更新失败，事务回滚，数据保持一致。

## 7. 返回响应
- 成功后，构建成功响应：
  ```json
  {
    "code": 200,
    "message": "重命名成功",
    "data": {
      "id": 123,
      "oldName": "旧文件名.pdf",
      "newName": "新文件名.pdf"
    }
  }
  ```
- 若过程中抛出任何异常，由全局异常处理器捕获并返回相应错误码和消息。

## 8. 异常处理说明
- **参数错误**: 返回400，提示具体原因（如新名称为空、含非法字符等）。
- **权限不足/记录不存在**: 返回403或404，提示无权限操作或资源不存在。
- **重名冲突**: 返回409，提示同一目录下已存在同名文件/文件夹。
- **服务器内部错误**: 返回500，并记录日志。

## 9. 数据库操作汇总
| 步骤 | 操作 | SQL示例 |
|------|------|---------|
| 权限校验 | 查询记录 | `SELECT id, path, name, type FROM folder WHERE id = #{id} AND user_id = #{userId}` |
| 冲突检查 | 检查重名 | `SELECT COUNT(*) FROM folder WHERE path = #{newPath} AND user_id = #{userId}` |
| 更新自身 | 更新name和path | `UPDATE folder SET name = #{newName}, path = #{newPath} WHERE id = #{id}` |
| 更新子项 | 批量更新路径 | `UPDATE folder SET path = REPLACE(path, #{oldPath}, #{newPath}) WHERE user_id = #{userId} AND path LIKE CONCAT(#{oldPath}, '/%')` |

## 10. 注意事项
- **索引**: `path` 和 `user_id` 字段应建立联合索引，以加速查询和更新。
- **性能**: 如果文件夹下子项极多（数万级别），批量更新可能锁表时间较长，可考虑分页更新或异步处理，但简单场景下直接更新即可。
- **根目录**: 若业务允许重命名根目录（`path = '/'`），需特殊处理父路径和路径拼接逻辑，建议禁止重命名根目录。
- **并发**: 高并发下可能出现竞态条件（如同时重命名同一文件夹及其子项），但通过事务和行锁可基本避免。如需更强一致性，可考虑在更新前对记录加锁（`SELECT ... FOR UPDATE`）。
